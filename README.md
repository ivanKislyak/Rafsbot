# Rafsbot

Telegram-бот на aiogram. Погода: `/weather` или `погода` (регистр и пробелы по краям не важны).
Бот отвечает одним сообщением для всех 16 городов в порядке списка `CITIES`.

## Запуск и проверка

Из корня проекта (Linux/macOS):

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Создайте `.env` по образцу `.env.example` и задайте `BOT_TOKEN`.
Не публикуйте токен. Запуск единственного экземпляра бота:

```bash
.venv/bin/python run.py
```

Если бот уже работает, перезапустите существующий процесс с обновлённым кодом;
не запускайте рядом второй polling-процесс с тем же токеном.
Отправьте `/weather` и `  ПоГоДа  `. Повторный запрос в течение 5 минут использует кеш.

Отдельная проверка настоящего погодного API и готового сообщения, без Telegram и токена:

```bash
.venv/bin/python weather.py
```

Автоматические проверки с подменой HTTP и Telegram, без polling и сети:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

## Как работает погода

1. Фильтры aiogram в `run.py` выбирают `cmd_weather` для `/weather` и слова «погода».
   Хендлер зарегистрирован перед остальными текстовыми хендлерами; новые общие
   обработчики текста размещайте после него.
2. `get_weather_message()` в `weather.py` возвращает кеш или создаёт одну общую
   асинхронную задачу обновления. Одновременные обращения ждут эту задачу.
3. `refresh_weather()` отправляет один запрос через `httpx.AsyncClient` с таймаутом
   10 секунд и проверкой HTTP-статуса. Координаты передаются списками;
   запрашиваются `temperature_2m`, `apparent_temperature`, `weather_code`, `is_day`.
4. JSON разбирается в список результатов. `location_id` (или порядок ответа при
   отсутствии ID) связывает результат с городом. Для каждого города форматируется
   одна строка с округлёнными температурами, эмодзи и описанием.
5. Хендлер отправляет готовый текст через `message.answer()`.

Кеш хранится только в памяти на 300 секунд после успешного обновления. При частичной
ошибке остальные города отображаются, а проблемные получают строку «данные временно
недоступны». Такой ответ тоже кешируется. Полный сбой не кешируется: пользователь
получает короткое сообщение с предложением повторить запрос. Подробности ошибок
попадают в лог процесса.

## Где менять города и эмодзи

- `weather.py`, список `CITIES`: `(название, широта, долгота)`. Порядок списка задаёт
  порядок строк. Координаты проверены 25.10.2026 через
  [геокодер Open-Meteo](https://open-meteo.com/en/docs/geocoding-api);
  комментарии содержат страну, область и GeoNames ID выбранной записи.
  Каменское — Kamyanske, ID 709932; Николаев — Mykolayiv (Mykolaiv), ID 700569;
  Ивантеевка Московской области — ID 555111. Геокодирование при запросах погоды
  не выполняется. Перед добавлением города проверьте страну и область геокодером.
- `weather.py`, словарь `WEATHER_CODES`: соответствие WMO-кодов эмодзи и коротким
  описаниям на русском по [официальной таблице Open-Meteo](https://open-meteo.com/en/docs#weathervariables).
  Включён и документированный код 97 (гроза). В `describe_weather()` код 0 ночью
  получает 🌙; неизвестный код — нейтральное описание.
- `CACHE_SECONDS` задаёт срок кеша; `format_temperature()` — запись температуры.

Функция `get_weather(latitude, longitude)` по-прежнему доступна для одной точки и
возвращает словарь `current`. Импорт `weather.py` не выполняет HTTP-запросы и не
запускает цикл событий. Новые зависимости не нужны: `httpx` уже есть в `requirements.txt`.
